## Executive judgment

**Functional beta with a substantially complete offline gameplay foundation. Not yet a verified production release candidate.** Concentrate on release-integrity, actual-phone multiplayer lifecycle and accessibility before implementing new optional game systems. Existing blank screen space below the Solo board is intentionally reserved by the owner for possible future contextual presentation; do **not** count that as a layout defect or fill it reflexively.

## Highest priorities: release blockers and confidence gaps

### P0 — Gate for a public release promising LAN multiplayer
1. **Full physical two-phone acceptance (not a confirmed coding bug):** both phones use *the same exact build* and Wi-Fi; Nearby versus manual fallback; optional room codes; host/guest identity, chat, simultaneous edits, Notes and safe Undo; both completion screens; actual next puzzle/rematch; host/guest background, force-stop and rejoin; saved room reuse and disconnected-state recovery. Document device/API, exact source/APK, both screens and pass/fail. Prior owner Co-op and one-sided Versus completion evidence are promising but do not close this matrix. Source: [issue #43](https://github.com/PlayerEden/SudokuTogether/issues/43), [LAN scope #12](https://github.com/PlayerEden/SudokuTogether/issues/12).
2. **Compatible signed release/update path:** validate original public app downloaded from itch.io against expected hash/certificate/package and version, build final update with the original production signer, increase release version code, test `adb install -r` while preserving real saved profiles, Solo/Daily, Notes, appearance and room data. Current `app/build.gradle.kts` defaults to versionCode **30** and versionName **1.0.0-beta.1** even while source and isolated preview are described as Beta 1.2. Existing QA update automation correctly refuses a substituted signer; the last recorded QA attempt lacked its signing secret and that prerequisite should be rechecked privately, not guessed. No APK re-signing or destructive uninstall. Source: [release issue #43](https://github.com/PlayerEden/SudokuTogether/issues/43), [build workflow](../.github/workflows/android.yml), [QA update workflow](../.github/workflows/qa-debug.yml).

### P1 — Strengthen ongoing development and accessibility
3. **Broaden mandatory checks:** `sudoku-core-ci.yml` only runs automatically on core/build path changes, `sudoku-versus-ui-ci.yml` is limited to Versus card/test paths; full Android visual/release workflows are manual. The main branch reports `protected=false` at this snapshot. Preserve the targeted PR #66 successes, but create a lean Android compile/unit test check for changes to `app/**`, core, Gradle and manifests; apply required PR checks/branch policy if permissions permit. Keep emulator suites budgeted and triggered by changed surfaces. [Core workflow](../.github/workflows/sudoku-core-ci.yml), [focused UI](../.github/workflows/sudoku-versus-ui-ci.yml).
4. **Real phone screen-reader, font and contrast review:** Compose large-font/compact tests and targeted pencil-mark color calculations exist, not a full TalkBack assessment. Examine all 81 cell descriptions, selected state, notes, Coach proof/strikethrough and unlock dialogs with TalkBack; test 320–430dp portrait, landscape, 100/130/200% text; board themes including dark themes, and Pencil/Terminal/Rose/Violet contrasts. [Board interaction notes](BETA12_PUZZLE_INTERACTION_AUDIT.md), [contrast QA](BETA12_C_PENCIL_CONTRAST_QA.md).
5. **Backup/recovery user expectations:** an explicit progress backup protects Solo/Daily and preferences, not independently the live host or guest room. Label this boundary plainly, test export+restore across same-phone and new-install scenarios, and ensure invalid files/low storage never overwrite good data. System backup is disabled deliberately for local-first control; explain that uninstall/data clearing without prior export loses local state. [Progress backup source](../app/src/main/java/com/playereden/sudokutogether/ProgressBackup.kt), [UI](../app/src/main/java/com/playereden/sudokutogether/ProgressBackupSettings.kt).
6. **Trusted-LAN security and disclosures:** wire protocol uses unencrypted framed JSON over TCP; six-digit code may be optional, and default setting is off. The host rate-limits incorrect code attempts and reconnect tokens exist, but do not promise encrypted private messaging. Verify trusted Wi-Fi assumptions and user-facing privacy policy, and consider default protected rooms or a simple warning on untrusted/shared Wi-Fi. No cloud transport in these flows is currently documented. [Protocol](../core/src/main/kotlin/com/playereden/sudokutogether/core/Protocol.kt), [HostServer](../core/src/main/kotlin/com/playereden/sudokutogether/core/HostServer.kt), [room code setting](../app/src/main/java/com/playereden/sudokutogether/GameViewModel.kt).

### P2 — Accuracy, longevity and finish polish
7. **Historical result awards calculation has an edge case:** `CompletionRewards.forRecord(records, finishedId)` compares *all current records* to the same list minus the displayed finish. For an older finish, later records remain in the "before" set. Example: finish A first and B later; reopening A now can omit the First Grid reward because B alone already meets its threshold. This is a code-derived flaw in retrospective presentation, **not** a demonstrated save-loss bug. Store a validated unlock event at completion or determine the prior chronological state with a stable ordering; add tests covering A→B→reopen A, backfilled legacy records, and deduplication. [Source](../core/src/main/kotlin/com/playereden/sudokutogether/core/CompletionHighlights.kt).
8. **Permanent ownership is not independently recorded:** `Cosmetics.progressAll` derives unlocks from `LocalPlayerData.records`, capped at 10,000. For existing modest thresholds this is unlikely to matter in short play, but if enough different outcomes crowd out earlier accomplishments, earned eligibility may regress. Before gift codes, rotating rewards or real claimed ownership, introduce a backwards-compatible entitlement ledger, migration, backup and idempotent claims. [Cosmetics](../core/src/main/kotlin/com/playereden/sudokutogether/core/Cosmetics.kt), [issue #50](https://github.com/PlayerEden/SudokuTogether/issues/50).
9. **Long-run performance:** full profiles may contain up to 10,000 records; progress saves are serialized/verified. Puzzle generation can evaluate up to 200 candidates for a chosen human-graded tier. These bounded paths should be benchmarked on an older/lower-RAM Android phone with a large fixture. No quantified lag or memory defect was reproduced by this audit. [PersonalPlay](../core/src/main/kotlin/com/playereden/sudokutogether/core/PersonalPlay.kt), [PuzzleSupply](../core/src/main/kotlin/com/playereden/sudokutogether/core/PuzzleSupply.kt).
10. **First-time experience:** keep the calm menu, clear board and intentionally open playing space. Test with someone unfamiliar with the project whether **Continue**, new difficulty selector, **New puzzle**, **Co-op** and **Versus** are understood without explanation. Prefer tiny copy/placement changes supported by observed confusion, not a redesign. [UX considerations](GRIDMATES_HOME_FIRST_IMPRESSION_USABILITY_CONSIDERATIONS.md).
11. **Documentation and version drift:** README still opens with November 16 / PR #42 as "current" while CONTINUE_HERE includes PR #66. Large historical docs are useful but should be archived/clearly dated; centralize short navigation for source truth, approved designs, pending proposals, and verified APKs. No need to rewrite historical work.

## Assets and presentation audit
- Current source registers **22 locally bundled, cohesive animal portrait PNGs**; `drawable-nodpi` contains all 22 named resources (12 Woodland, 6 Ocean, 4 Garden). Six font binaries cover the five selectable font families (Clear has separate bold clue weight). `app/src/main/assets/font_licenses.txt`, `docs/GRIDMATES_FONT_ASSETS.md`, and packaged asset hash manifests provide provenance and traceability. These are positive signs, **not a legal certification** of every illustration or final commercial rights.
- Forest/paper/cream design and green/gold hierarchy present a distinctive calm puzzle-book identity. Prior owner screenshots showed legible Home/Profile/Collection/board. The fresh Beta 1.2 Results APK is built and emulated, **not yet visually accepted** on the owner's actual phone. Avoid replacing the art wholesale.
- The Collection uses one familiar catalog model with family filters, unlocked/locked state and existing records-based milestones. Expand in curated thematic batches only after proving contrast and complete style-preview/equip behavior. Do not add random gifts/streak pressure just to fill page space.

## Explicitly proposed or deferred — do not call these shipped
- Shareable image result/profile cards and optional post-match share actions; full side-by-side opponent board comparison, which needs consent and careful protocol changes.
- QR invites; Split Clues (needs privacy validation); Bluetooth/Wi-Fi Direct without a router; remote matchmaking or cloud accounts; friends system.
- Redeem/gift codes, weekly gifts, enduring cosmetic entitlements, new Typewriter/Editorial font candidates and seasonal art beyond existing catalog.
- Rare interstitial ads and permanent Remove Ads purchase: the intended monetization direction is documented but the SDK/Billing/privacy/release implementation is not in the current source.

## Recommended sequence

| Phase | Concrete deliverable | Exit criteria |
| --- | --- | --- |
| A — Reliability gate | Owner two-phone Co-op/Versus matrix plus one-phone Solo/Daily/backup/resume and screen-reader walkthrough | Recorded builds, both device screenshots or video, reproducible bug tickets, blockers fixed |
| B — Release engineering | Permanent app checks, pinned/source-identified candidate, original signing continuity, genuine install-over with progress, Play privacy/permissions audit | Signed correct-package APK/AAB, increasing version code, preserved saves, reproducible test and artifact evidence |
| C — Light product polish | Retrospective results fix, targeted typography/contrast and beginner copy, performance fixtures | Automated regression + owner phone approval; no new features that complicate play |
| D — Optional growth | Better share cards, additional themes, permanent gifts/entitlements and monetization integration | Each item has explicit product approval, data/privacy implications resolved, complete regression and rollout proof |

**Release choice:** Either ship an excellent Solo + Daily product first and exclude/clearly beta-label LAN until its physical gate passes, or keep Co-op/Versus in the store promise and require the entire two-phone matrix before submission. Do not let decorative polish obscure this decision.
